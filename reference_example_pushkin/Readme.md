# Общее описание данных

Набор данных представляет собой аннотированные тексты первого тома энциклопедии,
посвященной произведениям А.С. Пушкина (Пушкинская энциклопедия: Произведения. Вып. 1. А – Д. —
СПб. : Нестор-История, 2009. — 520 с., ил.). Общее количество обработанных статей - 228. 
Исходные тексты были разделены на параграфы, после чего автоматически аннотированы 
с использованием библиотеки DeepPavlov для выделения следующих типов сущностей:

* **PER**: *(Персона)* — люди, такие как исторические фигуры, писатели, критики и комментаторы.
* **DATE**: *(Дата)* — все временные сущности, которые задают хронологическую структуру текста, такие как периоды и конкретные даты.
* **LOC**: *(Локация)* — регионы и местности, упомянутые в тексте, такие как города, страны названия рек, морей и другие географические названия.
* **ORG**: *(Организация)* — ассоциации и сообщества, упомянутые в тексте, такие как компании и учреждения, названия журналов и организаций 
(лицеи, училища, общества, издательства, и др.).
* **WORK-OF-ART**: *(Произведение искусства)* — произведения, связанные с текстом, такие как книги и художественные произведения.

В случае, если сущность является вложенной в другой тип сущности, то аннотируется
только верхнеуровневая сущность. Так, например, если в сущности, имеющий тип 
`WORK-OF-ART` (произведение), упомянута персоналия (`PER`), то она не аннотируется.

## Пример аннотирования текста для задачи NER

Рассмотрим наглядный пример из энциклопедической статьи.

### Исходный фрагмент текста

> «**Альфонс садится на коня...**» — Стихотворный фрагмент, в основу которого положен эпизод из романа Яна Потоцкого...

Семантический анализ.  В данном фрагменте слово **«Альфонс»** может
интерпретироваться двояко:

1. как имя персонажа (потенциальная сущность типа `PER`);
2. как часть названия художественного произведения  
   **«Альфонс садится на коня...»** (сущность типа `WORK-OF-ART`).

С точки зрения аннотирования для задачи NER важно учитывать следующее правило.

### Правило вложенных сущностей

В рамках используемой схемы разметки (BIO / CoNLL):

- сущности **не могут быть вложены** друг в друга;
- вложенные (nested) сущности **не размечаются**;
- если в одном фрагменте текста:
  - присутствуют две сущности,
  - и одна из них полностью входит в другую,
  — аннотируется только сущность **большего охвата**.

### Применение правила к примеру

В названии произведения:

```text
«Альфонс садится на коня...»
```

вся последовательность токенов образует **одну сущность**:

- тип: `WORK-OF-ART`;
- границы: от открывающей кавычки до закрывающей.

Отдельная разметка слова **«Альфонс»** как `PER` **не выполняется**, поскольку:

- оно является частью более длинной сущности;
- разметка вложенных сущностей в данном корпусе не поддерживается.

### Итоговая разметка (BIO)

```text
«           B-WORK-OF-ART
Альфонс     I-WORK-OF-ART
садится     I-WORK-OF-ART
на          I-WORK-OF-ART
коня        I-WORK-OF-ART
...         I-WORK-OF-ART
»           I-WORK-OF-ART
```


После аннотирования набор данных был проверен и верифицирован для исправления ошибок и обеспечения соответствия всех сущностей их тегам и позициям в тексте.

# Формат и структура данных

Набор данных представлен в файле `entities.json` и содержит 1567
объектов в формате JSON.  Каждый объект имеет следующую структуру,
адаптированную для обучения модели архитектуры BERT с использованием
фреймворка SpaCy:

* **text**: *str* — содержит текст, к которому применяется разметка.
* **entities**: *список списков* — включает сущности, найденные в тексте, с указанием их соответствующих позиций и типа.
* **tokens**: *список* — содержит токены, выделенные в тексте.
* **BIO-Tags**: *список* — содержит теги BIO для токенов, применяемые для аннотаций.

Entities представляют собой сущности, найденные в тексте. Каждая обнаруженная сущность представлена списком из трех значений в следующем порядке:

```[**start_span**, **end_span**, **entity_type**]```

где 
* start_span - индекс начала текстового фрагмента в тексте относительно 
начала текста, 
* end_span - индекс окончания текстового фрагмента в тексте,
* entity_type - тип сущности.

В дополнение создан скрипт для конвертации в формат CONLL, являющийся стандартным для 
задачи распознавания именованных сущностей. В результате работы скрипта 
в папке `encylopedia_ner_bio_dataset` формируются следующие папки: 

```
encylopedia_ner_bio_dataset/
├─ labels.txt (Типы сущностей)
├─ splits
│   ├── train.conll (Разметка CONLL)
│   ├── train.tsv — (упрощённый NER-TSV) (TOKEN<TAB>NER).
├─ raw/ (Исходные тексты)
├─ spans
│   ├── spans.jsonl (Разделение текста по фрагментам, 
                            соответствующим сущностям)
└─ scripts
    └── {check_bio.py,spans_to_bio.py} (скрипты проекта, 
                             не создаются автоматически)
```
Скрипт конвертации из формата SpaCy в формат CONLL представлен 
в файле `convert_to_conll.py` 

# Пример использования

## Зависимости 

```text
python <= 3.13
spacy==3.8.11
tqdm==4.67.1
matplotlib==3.10.8
pandas==2.3.3
ipywidgets==8.1.8
```

Для установки всех требуемых зависимостей, выполните команду

```shell
pip install -Ur requirements.txt
```

Скрипт `convert_to_conll.py` также осуществляет автоматическую проверку и установку отсутствующих зависимостей.  


## Использование набора данных в SpaCy 

Импортируйте модуль Pushkin_Dataset для работы с набором данных следующим образом:

```python
from Puskin_Dataset import *

path_to_dataset = "entities.json"
PD = Puskin_Dataset()
PD.load_dataset(path_to_dataset)
```

Получение количества сущностей и их идентификаторов:

```python
N = PD.number_of_samples
```

Получение информации о заданной сущности:

```python
text, entities, tokens, BIO_tags = PD.get_sample_by_id("10")
```

Визуализация сущностей 

```python
PD.display_tags(text, entities)
```
Получение всех сущностей заданного типа в наборе данных:

```python
PD.get_entites_by_type("LOC")
```

## Конвертация набора данных в формат CONLL

1. Для конвертации набора данных из формата json в jsonl выполните скрипт `convert_to_conll.py`. 

```shell
python convert_to_conll.py
```

2. Проверка результата конвертации и вывод статистики:

```shell
cd encyclopedia_ner_bio_dataset
python scripts/check_bio.py splits/train.conll
```
